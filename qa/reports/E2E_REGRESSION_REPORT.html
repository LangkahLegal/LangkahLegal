BUG-01CriticalPrivilege escalation: user mana pun dapat menjadikan dirinya admin lewat POST /auth/role Backend · Code review
Fitur
F05/F06 Role & Registrasi
Lokasi
backend/routers/auth.py:460 (update_role), backend/routers/auth.py:168 (sign_up), backend/schemas/auth.py:42 (RolePayload.role: str)
Verifikasi
Code review — tidak dieksploitasi agar data Supabase tidak berubah
Input
POST /api/v1/auth/role {"role":"admin"} (token client); juga POST /auth/signup dengan role='admin'
Expected
Backend hanya menerima role 'client' | 'konsultan', hanya untuk user yang belum punya role; perubahan ke 'admin' ditolak (403/422).
Actual
Nilai role disimpan apa adanya ke tabel users (tanpa whitelist & tanpa cek role sebelumnya). get_current_user membaca role dari tabel users sehingga _require_admin() lolos → akses penuh fitur admin (verifikasi konsultan, hapus dokumen hukum, data transaksi).
Dampak
Pengambilalihan penuh fungsi admin oleh user mana pun; integritas verifikasi konsultan & knowledge base AI rusak.
Rekomendasi
Gunakan Literal['client','konsultan'] pada RolePayload/SignUpPayload, tolak perubahan bila user sudah memiliki role, dan hanya izinkan penetapan admin lewat proses internal (service role / migrasi).
Langkah reproduksi
  1. Login sebagai client biasa (mendapat access_token).
  2. Kirim POST /api/v1/auth/role dengan body {"role":"admin"} dan header Authorization.
  3. Panggil GET /api/v1/admin/stats atau PATCH /api/v1/admin/consultants/{id}/verify.

Strategi & metodologi

  1. Inventaris fitur dari kode sumber (src/app, src/services, backend/routers) menjadi 36 fitur.
  2. E2E UI (mocked backend) — build produksi frontend dijalankan di browser; seluruh panggilan /api/v1/* dicegat MockApi sehingga skenario sukses, error 4xx/5xx, data kosong, data rusak, dan race condition dapat direproduksi. Setiap test memverifikasi UI dan payload request.
  3. Regression — defect terkonfirmasi ditandai knownDefect(); suite tetap hijau dan otomatis memberi tahu bila defect sudah diperbaiki. E2E_STRICT=1 menonaktifkan penanda ini.
  4. Edge case & negative — input ekstrem (500 karakter, emoji, XSS, SQL), file besar/berbahaya, klik ganda, token kedaluwarsa, data null, localStorage rusak, clock mocking.
  5. Live API non-destruktif ke backend FastAPI + Supabase; code review untuk logika berisiko yang tidak aman dieksploitasi.
